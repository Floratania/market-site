# Реальний каталог у локальному Saleor

08.10.2026 імпортовано **455 товарів** із групи «СКЛАД (ВІКНА,ДВЕРІ)»,
які мають додатну доступну кількість у Мамаївцях або Магалі.
**453 SKU опубліковано у 109 моделях** в каналі `vs-market-ua` із цінами прайсу
«Роздрібна ціна NEW» (UAH, ціна включає ПДВ).
**2 без ціни** збережено як неопубліковані чернетки.

Реальний каталог: http://127.0.0.1:8790/#catalog .
Демонстраційний каталог: http://127.0.0.1:8790/?demo=1 .
У демоперегляді додано посилання для переходу до реального каталогу.
Saleor Dashboard: http://127.0.0.1:9000/ — Products.

## Зіставлення

- `externalReference` товару/варіанта містить стабільні посилання 1С;
  імпортер використовує їх для оновлення без дублювання.
- SKU — код номенклатури 1С (в цій вибірці унікальний), а не довільний артикул.
- Публічна назва моделі формується точним правилом із назви номенклатури.
  Повна назва кожного SKU зберігається на його варіанті.
- Категорії «Вікна», «Двері», «Фрамуги» зіставлено явною картою
  `saleor-category-map.json`, після перегляду джерельних груп і прикладів.
- Варіанти з різними розмірами, оздобленням та R/L об'єднано в моделі.
  TS1 має 24 варіанти, TERNOPIL — 4, UMAN — 4. Префікси профілів, коди дизайну,
  невідомі суфікси та позначки якості не видаляються. Нечіткий пошук не застосовується.
  Усі 6 окремих характеристик 1С не мають додатного залишку і не імпортувалися.
- У приватних metadata зберігаються посилання 1С, необроблені розміри,
  резерви та час знімка. Міліметри підтверджені користувачем.
- 18 типів характеристик записано штатними атрибутами Saleor на варіантах.
  Основні розміри зіставлені з додатковими властивостями; суперечливі значення
  не публікуються, список — `product-dimension-conflicts.csv`.
- Завантажено 548 зображень із файлового тому 1С для 412 SKU, фото прив'язані
  до відповідних варіантів. Джерельні дублікати одного файлу всередині SKU усунуто.

Використано штатні Product/ProductVariant Saleor. Для локального перенесення
вже створених варіантів між товарними контейнерами виконано Django ORM-транзакцію:
ідентифікатори варіантів, SKU, ціни, складські записи та медіа збереглися.
Перед цим створено `pg_dump` у `integration/backups/`. Початкові контейнери
товарів збережено неопублікованими для відновлення; новий тип товару в Dashboard —
«Моделі VS Market з варіантами». Старі посилання перенаправляються на модель
з уже обраним SKU через `model-product-aliases.json`.

Каталог показує одну картку на модель та ціну «від»; фільтри застосовуються
до конкретних варіантів. На сторінці моделі є параметри розміру, кольору,
відкривання та повний вибір комплектації. Перемикаються саме SKU, фото, ціна
та наявність цього варіанта. У заявку передається його вихідний артикул 1С.

Основний імпорт виконано штатними мутаціями GraphQL `productBulkCreate`
(пакети по 30), `productUpdate`, `productVariantStocksUpdate` та іншими.
Використано лише локальний API `127.0.0.1:8000` і локальний канал UAH.
SQL Server/1С не змінювалися.

## Склади та залишки

Створено окремі склади `vsmarket-mamaivtsi` та `vsmarket-magala`,
додано їх до каналу VS Market і локальної зони Україна.
Відомі населені пункти записано; вулиця та індекс не вигадуються.
За проханням користувача поки залишено порожніми. Через вимоги адресної
валідації GraphQL початкові локальні склади створено Django ORM у транзакції,
із приватною позначкою `street-and-postcode-pending`.

Кількість — доступне `Количество` технічного регістру 1С без повторного
віднімання резерву. Усі кількості цілі; два від'ємних складських залишки
перенесено в Saleor як 0, вихідні значення збережені в приватних metadata.
Позитивна кількість іншого складу зберігається без зміни.

Відсутня TaxConfiguration каналу, який раніше створено локально ORM,
додана через `get_or_create`; підтверджено ціни з включеним податком.
Публічні `pricing.price.gross` усіх 453 товарів точно збігаються з 1С.

Сайт читає каталог із Saleor. Наявність по складах читається з
`saleor-import-stock.local.json` як **знімок із датою**, `stockVerified=false`.
На сторінці товару можна обрати склад та побачити кількість і час вивантаження.
Знімок не видається за живу перевірку 1С: підтвердження самовивозу перед
надсиланням заявки залишається вимкненим до підключення актуального bridge.
Менеджерський endpoint також ще не налаштовано.

## Повторний запуск

```text
node integration/sync-vsmarket-catalog.mjs
```

Імпорт вибирає останню папку вивантаження, відмовляється за старого (>1 години)
знімка, проблем зіставлення, дробових кількостей або конфліктів SKU.
Не перезаписує сторонні товари. Повторний запуск перевіряє зміни та оновлює
лише потрібні поля; повторний запуск для категорій створив 0 нових товарів.
Скрипт послідовно читає 1С, оновлює SKU, характеристики та фото, готує моделі,
створює резервну копію перед групуванням і перевіряє результат.
Повторне вивантаження 08.10.2026 та повторне групування підтверджено без
дублікатів SKU/моделей/фото. Якщо раніше опублікований SKU зникне зі свіжого
вивантаження або втратить ціну, імпорт зупиниться для перевірки: автоматично
видаляти ціни та обнуляти залишки він не буде. Періодичного запуску немає.

Звіти (секрети не логуються): `saleor-import-result.local.json`,
`saleor-import-verification.json`, `storefront-import-verification.json`.
Перевірено всі 455 записів у Saleor, усі 453 анонімно доступні ціни,
кількості двох складів, відсутність чернеток у публічній відповіді,
HTTP 200 окремої сторінки товару. Візуальну перевірку браузером не виконано.
Після групування `model-catalog-verification.json` підтверджує всі 453 ціни
та залишки; штатні атрибути та одиниці додатково звірено в PostgreSQL.
Сервер залишається локальним; на Linux нічого не розгорнуто.
