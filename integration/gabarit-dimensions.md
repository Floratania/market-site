# Розміри з габаритів 1С

Окремі додаткові реквізити «Ширина» й «Висота» залишаються основними. Для відсутніх значень використовуємо поля номенклатури. Перевірені одиниці: міліметри.

У частини товарів VS Market блок Д×Ш×В заповнюють двома розмірами виробу:

- `_Fld14051` (Длина, `LengthRaw`) = ширина виробу;
- `_Fld14105` (Ширина, `WidthRaw`) = висота виробу;
- `_Fld14047` (Высота, `HeightRaw`) = 0.

Цю схему застосовуємо тільки до вікон/дверей за назвою або групою номенклатури та коли пара в назві точно збігається з габаритами у тому самому порядку. Для інших або суперечливих записів зберігаємо issue, а не вгадуємо орієнтацію. Коли заповнені окремі реквізити, габарити їх не замінюють. Старий конфлікт повних полів WidthRaw/HeightRaw і реквізитів залишається у звіті конфліктів.

8 жовтня 2026 року підтверджено і точково оновлено 43 варіанти у 24 моделях локального Saleor. Приклад: `25-00000668`, «Сигара», 960×2050 мм, замість помилкової ширини 2050 та порожньої висоти. Пара записана в публічні specifications і рідні числові атрибути Saleor одиниці MM. Оновлені вихідні приховані товари та спільні розміри контейнерів моделей. Ціни, stock, media, SKU та модельні ID збережені й перевірені після імпорту.

Скрипти: `inspect-live-product-details.mjs` → `prepare-product-enrichment.mjs`. Повний ручний sync уже використовує цей ланцюжок. Для точкового повторного оновлення: `import-gabarit-dimensions.mjs` показує план; прапорець `--apply` застосовує його через Saleor API та записує резервну копію в `backups/`. `verify-gabarit-import.mjs` звіряє всі такі розміри через публічний API сайту.
