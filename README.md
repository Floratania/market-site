# VS Market — локальний сайт на основі Saleor

## Репозиторій і запуск на іншому комп’ютері

Репозиторій: https://github.com/Floratania/market-site

Потрібні Node.js 20+ і Docker Compose. Виконайте `npm install`, скопіюйте `.env.example` у `.env`, а `saleor-platform/backend.env.example` та `common.env.example` — у відповідні файли без `.example`. Замініть `CHANGE_ME` власними параметрами й секретами. Далі запустіть `npm run saleor:start` та `npm start`.

У Git не зберігаються база Saleor, дані покупців і замовлень, вивантаження облікової системи, паролі, токени, локальні налаштування та середовище `.runtime`. На новому комп’ютері потрібне окреме налаштування доступів та імпорт каталогу або відновлення бази. Готова база на цьому комп’ютері залишається без змін.

Поточний магазин має спрощену адмінку `/manage`, комплектації, кошик акаунта, оформлення замовлень, рекомендації, акції, редагування фотографій та налаштування повідомлень.

Покупці: зовнішні клієнти. Перша версія: каталог → кошик → заявка менеджеру. Для самовивозу покупець вибирає Мамаївці або Магалу; для іншого отримання місце зберігання не запитується.

## Локальний перегляд

Потрібен Node.js 20 або новіший. Залежностей для покупецького сайту немає.

Бренд: надане користувачем лого, акцент `#FF0000`, світла й темна теми. Перемикач у шапці зберігає вибір на цьому пристрої; перше відкриття використовує системну тему. Значок кошика використовується як окрема варіація бренду.

```text
node server.mjs
```

- Макет: http://127.0.0.1:8790/?demo=1
- Робочий каталог: http://127.0.0.1:8790/
- Вхід покупця: http://127.0.0.1:8790/account/login
- Реєстрація покупця: http://127.0.0.1:8790/account/register
- Кабінет: http://127.0.0.1:8790/account
- VS Code: відкрити `VS-Market.code-workspace`; F5 запускає сайт на порту 8791, щоб не конфліктувати з уже відкритим переглядом на 8790.

На цьому комп’ютері для VS Code налаштовано локальний Node.js у `.runtime/node/node.exe`. F5 використовує його напряму, а нові термінали VS Code отримують його в PATH. Якщо вже відкритий PowerShell не знаходить `node`, закрийте цей термінал і створіть новий або виконайте ` .\.runtime\node\node.exe start-saleor.mjs`.

Демо містить явно позначені вигадані товари й ціни. Заявки в демо вимкнено. Для роботи з Saleor скопіювати `.env.example` у `.env`, заповнити адреси та запустити:

```text
node --env-file=.env server.mjs
```

## Saleor локально

`saleor-platform/` — офіційний репозиторій https://github.com/saleor/saleor-platform для локальної розробки, початковий commit `ab6315bd59c58b4815175df4c679107ff9695be4`. Він містить API, Dashboard, PostgreSQL, Valkey та робочі служби. Docker Desktop 4.94.0 встановлено 07.10.2026 у режимі поточного користувача. Перший запуск очікує прийняття умов Docker користувачем. Порти в локальній копії обмежені адресою 127.0.0.1.

Команди виконуються в `saleor-platform/` після запуску Docker:

```text
docker compose -p vsmarket-local run --rm api python3 manage.py migrate
docker compose -p vsmarket-local run --rm api python3 manage.py createsuperuser
docker compose -p vsmarket-local up
```

API: http://localhost:8000/graphql/ . Dashboard: http://localhost:9000/ . Створити канал UAH, опублікувати товари й варіанти з унікальними SKU, встановити ціни в каналі. Вписати slug каналу в `SALEOR_CHANNEL`. Демо-дані Saleor не імпортуються автоматично.

Для запуску служб і міграцій одним кроком із папки сайту: `node start-saleor.mjs`. Цей скрипт не створює демонстраційних товарів і не видаляє даних.

Офіційний compose призначений лише для локальної розробки. Перед виробничим розгортанням потрібна окрема конфігурація доступу, сховища та резервного копіювання.

## Інтеграція з 1С

Вивантаження товарів і цін із прайсу **«Роздрібна ціна NEW»** виконано через SELECT. За вказівкою користувача включаються лише товари з додатною доступною кількістю в Мамаївцях або Магалі (`onlyInStock: true`). Команда повторного запуску з папки `storefront`: `node integration/export-catalog.mjs --export`. Файли зберігаються в `integration/exports/`, окремо від публічних файлів сайту. Формат, результати й межі — [catalog-export.md](integration/catalog-export.md). Вивантаження не імпортує дані в Saleor автоматично.

1С залишається джерелом SKU, цін і залишків. Синхронізація зіставляє SKU та стабільні посилання 1С із варіантами Saleor. Остаточні таблиці й правила вільного залишку ще потрібно перевірити на фактичній схемі `vsmarket_bi`.

Сайт використовує серверний `INVENTORY_API_URL`. Контракт відповіді описано в `integration-contract.md`. Без підтверджених залишків заявку на самовивіз не можна надіслати. Перед передаванням заявки менеджеру сервер повторно читає каталог і наявність. Ціни з браузера ігноруються.

## Оформлення замовлення та доставка

Окрема сторінка `/checkout`: контакти, кошик із точними комплектаціями, Нова пошта у відділення або кур’єром, самовивіз та отримання за погодженням. Є живий пошук міст і відділень Нової пошти. Замовлення зберігаються до надсилання email і Telegram, із повторними спробами після помилки. Одержувач email — `tania.flyora@gmail.com`. Поштовий пароль додатка та бот ще потребують заповнення в приватному `integration/order-settings.local.json`; користувач відклав цей крок. До підключення сповіщень приймання працює зі збереженням на цьому комп’ютері у `integration/orders/`. Інструкція — [checkout-and-notifications.md](integration/checkout-and-notifications.md).

## Вхід і реєстрація покупців

Кнопка «Увійти» у шапці веде до реєстрації та входу через Saleor. Є підтвердження email, кабінет зі зміною імені та прізвища, відновлення пароля і вихід. Покупецький пароль не пов’язаний з локальними даними адміністратора Saleor або pgAdmin.

Локальні листи переглядати в Mailpit: http://127.0.0.1:8025/. Вони не відправляються на зовнішні адреси. Налаштування, перевірки та обмеження локальної сесії — [customer-auth.md](integration/customer-auth.md).

## Рекомендації

У публічних metadata товару Saleor:

- `cross_sell_skus`: артикули супутніх товарів через кому.
- `upsell_skus`: артикули рекомендованих альтернатив через кому.

Ці зв’язки використовуються в картці товару та кошику. Для вікон і дверей рекомендації задаються явними зв’язками після перевірки сумісності: розміри, тип профілю, фурнітура, напрям відкривання. Автоматичного підбору лише за вищою ціною немає. Персоналізація за історією покупок ще не реалізована.

## Заявки

`MANAGER_WEBHOOK_URL` — серверний endpoint, який приймає заявку й підтверджує її збереження кодом HTTP 2xx. Він може бути workflow n8n для Telegram або email. Секрет webhook зберігається лише в серверному середовищі. Зараз адреса одержувача не налаштована; реальні заявки не надсилаються.

## Перевірка

```text
node --check server.mjs
node --check public/app.js
node --test tests/integration.test.mjs
```

Інтеграційна перевірка використовує лише локальні підставні джерела й перевіряє відмову за недостатнього залишку та серверну ціну заявки.

Поточний стан: локальна вітрина, Saleor runtime та облікові записи покупців працюють. У локальний Saleor імпортовано 455 реальних товарів із залишками двох складів: 453 опубліковано з цінами UAH, 2 без ціни — чернетки. Перегляд реального каталогу: http://127.0.0.1:8790/#catalog (без `?demo=1`). Постійна синхронізація з 1С та канал отримання заявок ще не підключені. На робочий Linux-сервер цей проєкт не публікувався. Про імпорт і перевірки — [saleor-catalog-import.md](integration/saleor-catalog-import.md).

## Проста адмінка
